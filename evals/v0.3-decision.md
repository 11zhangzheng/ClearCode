# v0.3 deterministic-check decision

Decision date: 2026-10-13
Outcome: **do not create or tag v0.3.0 yet**.

The plan permits a deterministic product check only when the same Skill rule is
missed in at least two independent tasks and the consequence is clear and
deterministically detectable.

Evidence reviewed:

- eight v0.1 baseline/Skill pairs;
- five v0.2 high-value regression runs;
- three natural and two negative trigger runs for both v0.1 and v0.2;
- six consecutive changes to the ClearCode evaluation workflow.

No candidate crossed the threshold:

| Candidate rule | Confirmed independent misses | Decision |
| --- | ---: | --- |
| Reuse an existing business rule | 0 | no script |
| Keep provider details at the adapter boundary | 0 | no script |
| Remove all directly related active paths | 0 | no script |
| Report failed/unavailable verification honestly | 0 | no script |
| Keep low-risk changes proportionate | 0 | no script |

The PowerShell runner issues were evaluation-infrastructure defects, not repeated
failures by the Skill on repository tasks. The evaluation runner is not installed
with the Skill and does not enforce project code policy.

Reopen v0.3 when two independent real tasks miss the same rule. Record their raw
diffs and consequences first; then prefer an existing formatter, linter, test, or
repository command before writing a new checker.
